# Turn-State 机制

[返回首页](../README.md)

本文说明当前代码行为。早期关于 Token 池、每条请求消耗一个 Token、30 分钟自动失效的实验方案，已不适用于当前实现。

## 获取与缓存

应用使用当前工作目录中的 ChatGPT 凭据，通过所选出站代理向上游 `/responses` 发起轻量请求，从响应头读取 `x-codex-turn-state`。

- 无缓存时，每轮最多并发 10 路获取；成功后取消剩余任务。
- 候选值必须能解析时间戳，并排除长度为 308～316 字符的值。
- 当前只保存一个 Token，内存与本地文件同步，启动时尝试恢复。
- 有缓存时约每 30 秒巡检并继续复用；一轮获取全失败后立即进入下一轮。
- 切换工作目录、出站地址、出站模式或上游配置等会清空缓存并重新获取。

获取成功的判断以响应头及 Token 解析结果为准，并非单独以 HTTP 200 为准。探测使用账号授权发起真实请求，不应视为无成本的本地检查。

## 请求处理

| 流量 | 当前规则 |
| --- | --- |
| HTTP `POST`，路径包含 `/responses` | 仅在客户端已携带 Turn-State 时，用缓存替换 |
| HTTP 首次请求未携带 Turn-State | 保持未携带状态 |
| WebSocket 握手 | 移除握手中的 Turn-State 请求头 |
| WebSocket JSON 对象 | 已有 `client_metadata["x-codex-turn-state"]` 时尝试替换 |
| 非 JSON、二进制消息或没有可替换值 | 原样转发 |
| 上游业务响应 | 不用于采集或更新本地 Token 缓存 |

没有缓存时保留客户端原值。缓存会重复使用，不会按请求消耗；代理层仍会按 HTTP 转发要求处理连接相关头。

## 当前边界

- **没有按年龄失效**：当前读取缓存不执行 TTL 校验，界面显示的年龄不是服务端有效性证明。
- **没有自动拒绝检测**：HTTP 401/403 和 WebSocket 响应尚未接入自动清空、刷新逻辑。
- **没有启用动态出口轮换**：源码中的代理会话随机化辅助函数未被当前获取流程调用。
- **长度是筛选规则**：界面中的“292”“312/降智”是项目标签，不是模型能力或计算档位的官方指标。当前代码排除 308～316 字符的值，并不严格限定只接收 292 字符。

本工具以缓解使用问题为目标，不改变账号套餐、配额或模型本身，也不保证消除上游过载。历史实验中的地区、长度和单题回答差异不足以证明模型能力变化，不能作为稳定效果承诺。
